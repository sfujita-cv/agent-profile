# 個人共通ルール

- 変更前に既存コード・設定・ドキュメントを読み、現在の設計意図と制約を確認する。
- 要求を満たす最小の変更を優先し、無関係なリファクタリングを同時に行わない。
- 既存の public API、データ形式、実行手順を変更する場合は互換性への影響を明示する。
- 実行していない検証を実行済みとして報告しない。未実施なら理由と残課題を分けて書く。
- 再現可能なコマンドと根拠を残す。性能比較では入力、ハードウェア、warm/cold、反復条件を揃える。
- README、設計書、作業報告などの文章は原則日本語で記述する。コードコメントと識別子は英語を使う。
- パッケージやシステム依存を勝手に global install しない。対象リポジトリが定める環境管理方式を優先する。
- 破壊的 Git 操作、既存 worktree の削除、既存 branch の削除、force push は明示要求がない限り行わない。
